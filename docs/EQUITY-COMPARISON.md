### Decision Framework

## Part 4: How to Capture Volatility (What Needs to Change)

The current system fails to capture swing profits because of four structural limitations. Here is what needs to change, in priority order.

### Problem 1: Fixed Take-Profit Exits Too Early

**Current behavior:** The system exits at 1.0-2.6x ATR from entry. On BTC at ATR ~$2,000, that means exit at +$2,000 to +$5,200 profit. But BTC regularly makes $20,000-$40,000 moves (the top swings we identified).

**Solution: Trailing Stop Exit Mode**

When the system detects a strong trend:
1. Enter normally (same signal pipeline)
2. Instead of a fixed TP, use a trailing stop at 2x ATR below the running high
3. The stop moves UP as price moves up, but never moves down
4. Exit only when price retraces 2x ATR from its highest point

**Impact estimate:** A trailing stop on the Sep-Dec 2024 BTC rally (+99.6%) would capture approximately 60-70% of the move instead of the current 2-5%. On a $10,000 position risking 1%, that's ~$600-700 profit vs the current ~$100.

**Implementation:** Add `exit_mode: "trailing"` option to `RiskConfig`. When active, the replay/position manager uses a trailing stop instead of fixed TP. The trigger to switch modes: **when the asset's 50 EMA is above the 200 EMA and the 200 EMA slope is positive for 20+ bars.**

### Problem 2: Position Sizing Too Conservative for Trends

**Current behavior:** Risk 1% per trade regardless of conviction level. 1% risk with 1x R:R = 1% gain per winning trade. Even with 62% win rate and 21 trades on BTC over 5 years, max gross gain is about 21 x 0.62 x 1% = 13%.

**Solution: Tiered Position Sizing**

| Signal Quality | Confluence | Trend Alignment | Position Size |
|---------------|-----------|-----------------|--------------|
| Standard | 50-69 | Any | 1% risk (current) |
| High conviction | 70+ | With trend | 2% risk |
| Maximum conviction | 70+ | With trend + regime trending + multi-TF alignment | 3% risk |

**Impact estimate:** Doubling position size on high-conviction signals would roughly double returns on those trades. If the top 30% of trades (by confluence) used 2% risk, overall returns would increase by approximately 30%.

**Implementation:** Already partially supported by `max_risk_per_trade` in `RiskConfig`. Need to make it dynamic based on confluence score and trend alignment.

### Problem 3: No Trend-Following Mode

**Current behavior:** Every trade is treated the same -- enter, set TP/SL, wait. Whether BTC is in a 6-month rally or a 2-day bounce, the system exits at the same fixed target.

**Solution: Dual-Mode Operation**

**Mode 1: Swing Trading (current, improved)**
- For corrections, ranging markets, counter-trend bounces
- Fixed R:R exits (1.0-2.618x ATR)
- 1% risk per trade
- Active in: ranging, transitioning, or counter-trend conditions

**Mode 2: Trend Following (new)**
- For confirmed strong trends
- Trailing stop exit (2x ATR trailing, no fixed TP)
- 2-3% risk per trade
- Scale in: add to position on pullbacks within the trend
- Active in: trending regime + 50 EMA > 200 EMA + positive slope

**Detection criteria for Mode 2:**
1. Regime = "trending" for 20+ consecutive bars
2. 50 EMA > 200 EMA (bullish) or 50 EMA < 200 EMA (bearish)
3. 200 EMA slope confirms direction (positive slope = only BUY, negative = only SELL)
4. ADX > 30 (strong trend)

When ALL four conditions are met, switch to trend-following mode. When any condition breaks, revert to swing trading mode.

**Implementation:** Add `trend_following_mode` logic to `pipeline.py`. When active:
- Direction filter: only trade WITH the trend (BUY in bull, SELL in bear)
- Exit strategy: trailing stop instead of fixed TP
- Position sizing: 2-3% risk
- Scaling: allow adding to winners on pullback signals

### Problem 4: No Compounding

**Current behavior:** Position size is calculated as `capital * risk_pct / risk_distance`. But `capital` doesn't compound -- after a winning trade, the next trade uses the same absolute risk.

**Solution: Equity-Based Position Sizing**

Position size should be based on CURRENT equity, not initial capital. After a winning streak grows equity from $10,000 to $11,000, the next trade should risk 1% of $11,000 ($110) not 1% of $10,000 ($100).

**Impact estimate:** With compounding, the system's +16.1% over 5 years would become approximately +17.5% (modest improvement due to low base returns). However, combined with trailing stops and higher conviction sizing, compounding's effect multiplies significantly.

**Implementation:** Already the behavior in replay() -- `capital * risk_pct / risk_dist` uses current capital. Confirm this is also the case in production's `position_manager.py`.

## Part 5: Regime Detection -- How to Know When to Activate

The system already has regime detection (ADX-based: trending/ranging/transitioning/chaotic). But it needs a HIGHER-LEVEL regime classifier that determines whether to use SignalForge at all.

### Proposed Macro Regime Indicator

Calculate these on a rolling basis (daily close, 200-bar lookback):

| Indicator | Bull Signal | Bear Signal | Neutral |
|-----------|-----------|-----------|---------|
| Price vs 200 EMA | Price > 200 EMA | Price < 200 EMA | Near 200 EMA |
| 200 EMA slope (20-bar) | Positive | Negative | Flat |
| Distance from ATH | < 10% | > 30% | 10-30% |
| 50/200 EMA cross | Golden cross | Death cross | -- |
| ADX (14) | > 25 (trending) | > 25 (trending) | < 20 (ranging) |

### Macro Regime Classification

| Regime | Conditions | Strategy | Position Size |
|--------|-----------|----------|--------------|
| **STRONG BULL** | Price > 200 EMA, slope positive, < 10% from ATH | B&H with trailing stop OR trend-follow mode | 2-3% risk, long only |
| **BULL CORRECTION** | Price > 200 EMA but > 10% from ATH, slope positive | SignalForge swing trading | 1-2% risk, long bias |
| **RANGING** | ADX < 20, price near 200 EMA, flat slope | SignalForge with high confluence (70+) | 1% risk, both directions |
| **BEAR TRENDING** | Price < 200 EMA, slope negative, > 30% from ATH | SignalForge actively | 1-2% risk, short bias |
| **CAPITULATION** | Price < 200 EMA, > 50% from ATH, extreme volume | Reduce exposure, wait for reversal signals | 0.5% risk or cash |
| **RECOVERY** | Price crossing above 200 EMA, death cross reversing | Transition from SignalForge to trend-follow | 1-2% risk, long only |

### Implementation: Macro Regime Detector

```
File: backend/app/engine/layers/macro_regime.py

class MacroRegime:
    STRONG_BULL = "strong_bull"       # B&H / trend-follow
    BULL_CORRECTION = "bull_correction"  # SignalForge active
    RANGING = "ranging"              # SignalForge selective
    BEAR_TRENDING = "bear_trending"  # SignalForge active
    CAPITULATION = "capitulation"    # Reduce exposure
    RECOVERY = "recovery"           # Transition to trend-follow

def detect_macro_regime(candles, ath_lookback=500):
    ema_200 = compute_ema(candles.close, 200)
    ema_50 = compute_ema(candles.close, 50)
    adx = compute_adx(candles, 14)

    current_price = candles.close.iloc[-1]
    ema_200_current = ema_200.iloc[-1]
    ema_200_slope = (ema_200.iloc[-1] - ema_200.iloc[-20]) / ema_200.iloc[-20]
    ath = candles.close.rolling(ath_lookback).max().iloc[-1]
    dd_from_ath = (ath - current_price) / ath

    if current_price > ema_200_current and ema_200_slope > 0.01:
        if dd_from_ath < 0.10:
            return MacroRegime.STRONG_BULL
        else:
            return MacroRegime.BULL_CORRECTION
    elif current_price < ema_200_current and ema_200_slope < -0.01:
        if dd_from_ath > 0.50:
            return MacroRegime.CAPITULATION
        else:
            return MacroRegime.BEAR_TRENDING
    elif current_price > ema_200_current and ema_200_slope < 0:
        return MacroRegime.RECOVERY
    else:
        return MacroRegime.RANGING
```

### Integration into Pipeline

```
File: backend/app/tasks/run_pipeline.py

# Before signal generation:
macro = detect_macro_regime(candles)

if macro == MacroRegime.STRONG_BULL:
    # Option A: Skip SignalForge, recommend B&H

    config["direction_filter"] = "long_only"
    config["exit_mode"] = "trailing"

elif macro in (MacroRegime.BULL_CORRECTION, MacroRegime.BEAR_TRENDING):

    config["exit_mode"] = "fixed"

elif macro == MacroRegime.RANGING:
    # Raise bar for entry
    config["min_confluence"] = max(config["min_confluence"], 70)

elif macro == MacroRegime.CAPITULATION:
    # Reduce risk dramatically
    config["max_risk_per_trade"] = 0.005
```
